Public UI

Cart UI

---

2. Mandatory dynamic features

A) Product Listing via Hygraph (Mandatory)

All products must load from Hygraph.

Flow:

1. NestJS fetches product data from Hygraph
2. Frontend requests products from NestJS using RTK Query
3. Products render dynamically in UI

Hard rules:

* ❌ No hardcoded products
* ❌ No direct Hygraph calls from frontend
* ✅ Hygraph access happens only in backend

---

B) Cart Functionality (Mandatory)

Cart must be fully functional.

Required behavior:

* Add product to cart
* Increase / decrease quantity
* Remove product from cart
* Persist cart state (backend-driven)

Flow:

1. User interacts with cart UI
2. Frontend calls NestJS via RTK Query
3. Backend stores and returns cart state
4. UI updates correctly

Rules:

* ❌ No checkout
* ❌ No localStorage-only cart
* ✅ Cart data must come from backend APIs

4. Technology explanation

Hygraph

Headless CMS used as the single source of truth for products.

* Products are created in Hygraph
* Backend fetches products via GraphQL
* Frontend never talks to Hygraph directly

---

RTK Query

Central API layer responsible for:

* Fetching products
* Managing cart state
* Caching responses
* Handling loading and errors

---

Next.js (App Router)

Used for:

* File-based routing
* Component composition
* Scalable frontend architecture

---

NestJS

Used for:

* Clean API structure
* External service integration (Hygraph)
* Cart state management

---

Material UI

Used for:

* Layout and grid system
* Product cards
* Buttons and inputs
